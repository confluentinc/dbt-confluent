`streaming_table` now runs dbt's contract check before re-submitting a missing or stopped INSERT, as it already did before `create table`, whatever `on_schema_drift` is set to. A restart now fails with dbt's contract error if the SELECT and the yml `columns` disagree, including an adopted table whose yml lists no `columns`, only some of them, or a column without its `data_type`: list every SELECT column in the yml, with its `data_type`, to fix it. Each restart also makes two more schema queries.
