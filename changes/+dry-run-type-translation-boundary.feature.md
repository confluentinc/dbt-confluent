Split dry-run type translation into two independently-tested capabilities: `dry_run.get_ddl_type`, which always succeeds in reconstructing valid Flink DDL for any type a dry run can report (recursing into `ARRAY`/`MULTISET`/`MAP`/`ROW`'s element/key/value/field types and each level's own nullability, appending `NOT NULL` where the source column had it, and mapping `INTERVAL_YEAR_MONTH`/`INTERVAL_DAY_TIME` to their one real canonical form) except the two genuinely unconstructable `RAW`/`TIMESTAMP_WITH_TIME_ZONE`; and `dry_run.try_get_castable_type`, the stricter function `get_tested_model_columns` actually needs for unit test fixtures, which additionally rejects the constructed/interval types since no YAML-spellable fixture value can ever be `CAST` into them (confirmed live), even though their DDL form is otherwise valid - and always ignores nullability, since a CAST target can't carry a `NOT NULL` constraint (a `PRIMARY KEY` source column, entirely ordinary in a real model, would otherwise turn into invalid `CAST(x AS BIGINT NOT NULL)` SQL). Both guarantees are proven by independent, exhaustive functional tests against a live Confluent Cloud environment: one recreates an equivalent table from the reconstructed DDL (parameterized over nullable and `NOT NULL` columns) and confirms its dry-run schema matches exactly, the other casts a representative YAML-style literal - rendered through dbt-core's own `format_row` macro, not a reimplementation of it - into every storable type and confirms it either succeeds with the correct resulting type or raises as expected.
