The schema drift check no longer reports drift on every re-run of a Protobuf (`'value.format' = 'proto-registry'`) `streaming_table` with a `CHAR` or `VARCHAR` MAP key or `MULTISET` element. At those positions, the model's type now passes if it fits in the table's definition (a `VARCHAR` at least as long, or the same `CHAR`), ignoring nullability. A longer `VARCHAR` key or element, or a different `CHAR` length, is still reported but a shorter `VARCHAR` isn't. See MATERIALIZATIONS.md#schema-drift-detection.
