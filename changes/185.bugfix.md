The schema drift check no longer reports drift on every re-run of a Protobuf (`'value.format' = 'proto-registry'`) `streaming_table` with a `CHAR` or `VARCHAR` MAP key or `MULTISET` element. At those positions the model's type now passes if it fits in the table's (a `VARCHAR` at least as long, or the same `CHAR`), ignoring nullability, so a longer key or element is still reported but a shorter one isn't. See MATERIALIZATIONS.md#schema-drift-detection.
