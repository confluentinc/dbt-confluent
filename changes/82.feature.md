Add a `tableflow` config for `table`, `streaming_table`, `streaming_source`, and `materialized_table` to enable [Tableflow](https://www.confluent.io/product/tableflow/) on a model's backing Kafka topic, materializing it as an Iceberg and/or Delta Lake table. Checked on every run: enabled fresh if not already enabled, or a warning if it's already enabled (in-place updates aren't supported yet — use `--full-refresh`). Before a `--full-refresh` drop, if the model still configures `tableflow`, the adapter disables it first so the drop doesn't race an active materialization. Enabling and disabling both block by default (up to 300s) waiting for the topic to reach its terminal state, so both log at info level (not just `--debug`) to make the wait visible. See MATERIALIZATIONS.md.
