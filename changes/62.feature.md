Add a `materialized_table` materialization built on Flink's `CREATE OR ALTER MATERIALIZED TABLE ... AS SELECT`. It is declarative: every run re-asserts the definition and lets Flink reconcile it — a new table is created, any change is evolved in place, and an unchanged definition is a server-side no-op. `--full-refresh` drops and recreates, which is required to change `distributed_by` and to rebuild a *stateful* model correctly after a definition change (an in-place evolution silently resets processing state); note the drop permanently deletes the backing Kafka topic and its data. Supports `config(distributed_by={...}, with={...}, start_mode=...)`, and switching a model to or from `materialized_table` is guarded in both directions (the run fails with guidance; `--full-refresh` performs the switch). See MATERIALIZATIONS.md for details.
