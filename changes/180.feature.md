Add `artifact_path` to the `function` materialization, so dbt uploads a local Java JAR or Python ZIP as the function's artifact (named by content hash, so unchanged packages are reused; a replaced package's old artifact is kept, since running statements stay bound to it, and `dbt run-operation cleanup_function_artifacts` lists or deletes artifacts no function uses) instead of requiring a pre-uploaded `artifact_id`. A function replaced with a nonexistent `artifact_id` now fails before the existing function is dropped. While a function with an `artifact_path` is replaced, a journal in the new artifact's description records the function to put back, so a failed re-create restores it and a run that dies part way is finished (or undone) by the next one.
