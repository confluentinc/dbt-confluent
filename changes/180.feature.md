Add `artifact_path` to the `function` materialization, so dbt uploads a local Java JAR or Python ZIP as the function's artifact (named by content hash, so unchanged packages are reused; a replaced package's old artifact is kept, since running statements stay bound to it) instead of requiring a pre-uploaded `artifact_id`. A function replaced with a nonexistent artifact now fails before the existing function is dropped, and a failed replacement restores the previous function.
