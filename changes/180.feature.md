Add `artifact_path` to the `function` materialization, so dbt uploads a local Java JAR or Python ZIP as the function's artifact
(named after the project, the file's name and a hash of its content, so unchanged packages are reused)
instead of requiring a pre-uploaded `artifact_id`. A function replaced with a nonexistent `artifact_id` now fails before the existing function is dropped.
Both the upload and this check use the artifact API, which needs `auth: oauth` or a Global API key; the `function` materialization checks for one up front.
