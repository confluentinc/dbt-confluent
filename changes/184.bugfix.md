`streaming_table` now writes its columns by name. Its INSERT names the yml `columns` and selects them from the model's SQL (`INSERT INTO <table> (<columns>) SELECT <columns> FROM (<model SQL>)`). Before, Flink matched the INSERT to the table by position, so when the SELECT returned two columns of the same type in a different order from the yml (or, on a restart, from the existing table), each was written into the other's column without an error. Upgrading: a `streaming_table` whose SELECT listed its columns in a different order from its yml has been writing values into the wrong columns, and its running INSERT keeps doing so after the upgrade, because a run that skips leaves it alone. To fix it, run the model with `--full-refresh`, which drops the table and its data and rebuilds it from the source. Stopping the statement, so that the next run re-submits it, fixes new rows but keeps the rows already written. See MATERIALIZATIONS.md#streaming-table.
