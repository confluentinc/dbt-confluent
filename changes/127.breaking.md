Replace `statement_name_prefix` with an optional `resource_name_prefix` profile option, so several developers or CI runs can build the same project against one cluster without clobbering each other. When set, it is prepended to every Kafka topic and Flink statement name the project creates, including explicit `alias` and `statement_name` configs, so a dev or CI target never touches production's resources. It defaults to empty, which leaves topic names and explicit names unchanged, but generated statement names lose their old `dbt-` prefix (`dbt-<project>-<model>` becomes `<project>-<model>`), so the next run starts new statements while the old `dbt-` ones keep running until stopped manually. Profiles that still set `statement_name_prefix` now fail to load: rename the key to `resource_name_prefix`.
