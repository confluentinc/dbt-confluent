Replace `statement_name_prefix` with an optional `resource_name_prefix` that isolates environments (e.g. developers) sharing one cluster. When set, it is prepended to every topic and statement name, including explicit `alias` and `statement_name`. It defaults to empty, so generated statement names drop the old `dbt-` prefix (`dbt-<project>-<model>` becomes `<project>-<model>`): the next run starts new statements and the old ones keep running until stopped. Profiles setting `statement_name_prefix` now fail to load; note that moving its value to `resource_name_prefix` also prefixes topic names. The prefix may only contain lowercase letters, digits and hyphens (starting with a letter or digit, at most 64 characters), so it is valid in both topic and statement names. Topic names use the prefix with hyphens replaced by underscores (`alice-` gives `alice_orders`), so ephemeral model names stay valid in SQL.
