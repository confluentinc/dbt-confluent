The schema drift check for `table` and `streaming_table` models now gets the expected columns from a Flink `sql.dry-run` of the model's SELECT instead of creating and introspecting a temporary table, so a re-run no longer creates (and later drops) a `__dbt_tmp_schema_check_<model>` table per model. The dry-run evaluates the SELECT in the mode the model is built in (snapshot for `table`, `streaming_query` for `streaming_table`), which changes behaviour in three cases: a `table` whose SELECT only works as a streaming query now fails the drift check (its `--full-refresh` already fails); a `table` whose SELECT only works as a snapshot query no longer fails it; and the profile's or model's `execution_mode` no longer affects the drift check for these models. The temporary table remains the fallback for `streaming_source` models and wherever the dry-run can't stand in for it (no result schema, duplicate column names, or a column type whose `INFORMATION_SCHEMA` spelling hasn't been verified), and the dry-run path also reclaims a temp table leaked by an earlier run that died hard. See MATERIALIZATIONS.md#schema-drift-detection.
