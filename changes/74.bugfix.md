`view` now updates an existing view in place with `ALTER VIEW ... AS` instead of dropping it and creating it again. Before, the view was dropped first, so when the new SQL failed (a server-rejected query, or an enforced contract that no longer matched) the run left no view at all, and anything reading it broke until the model was fixed. Now the run fails and the previous view keeps serving. A first run, or a model switching from another materialization to `view`, still creates the view as before, and `--full-refresh` still drops the view and creates it again, as it does for the other materializations. See MATERIALIZATIONS.md#view-statements-emitted.
