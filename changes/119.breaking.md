`streaming_table` now detects a change to a model's SQL logic, such as a new `WHERE` clause, by comparing the INSERT its running statement currently executes with the INSERT dbt would submit now; only comments and whitespace are ignored. Under the default `on_schema_drift='fail'`, the run fails instead of skipping the model while the old SQL keeps running; the error message shows both statements. On upgrade, a `streaming_table` whose running statement doesn't match, e.g. one edited previously without using `--full-refresh`, deployed before 0.5.0, or adopted with different SQL, fails its first run. To apply the model's SQL, run with `--full-refresh` (deletes the topic and its data); to keep the running statement, set `on_schema_drift='ignore'`. See MATERIALIZATIONS.md#query-logic-changes.
