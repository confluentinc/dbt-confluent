`streaming_table` now detects a change to a model's SQL logic, such as a new `WHERE` clause, by comparing the model's compiled SQL with the SQL its running statement executes (comments, whitespace and the case of reserved keywords are ignored). Under the default `on_schema_drift='fail'`, the run fails instead of skipping the model while the old SQL keeps running; the error shows both SQL texts. On upgrade, a `streaming_table` whose running statement doesn't match the model's current SQL, for example one edited earlier without `--full-refresh` or adopted with different SQL, fails its first run. To apply the model's SQL, stop or delete the statement and re-run once it's stopped or gone (the table is kept, but the statement likely re-reads its sources from the beginning), or run with `--full-refresh` (deletes the topic and its data); to keep the running statement, set `on_schema_drift='ignore'`. See MATERIALIZATIONS.md#query-logic-changes.
