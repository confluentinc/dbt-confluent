`streaming_table` now detects a change to a model's SQL logic, such as a new `WHERE` clause, by comparing the model's compiled SQL with the SQL its running statement executes. Under the default `on_schema_drift='fail'` the run fails and points to `--full-refresh`, instead of skipping the model while the old SQL keeps running. This also applies to adopted statements whose SQL doesn't match the model's; set `on_schema_drift='ignore'` to keep them as they are. See MATERIALIZATIONS.md#query-logic-changes.
