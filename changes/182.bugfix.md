dbt's contract check no longer rejects a `CHAR(n)` or `BINARY(n)` column (e.g. a string literal like `'abc'` or a binary literal like `x'0102'`) for a column declared `string`/`varchar` or `bytes`/`varbinary`. Flink types a literal as `CHAR(n)` or `BINARY(n)`, so the model needed `CAST('abc' AS STRING)`. The schema drift check for a `streaming_table` or a `table` with an enforced contract accepts the same columns, so these models also re-run without reporting drift. A literal for a `varchar(n)` or `varbinary(n)` column below the maximum length is still rejected, as before: the check doesn't compare lengths, and Flink silently truncates a value longer than `n`. See MATERIALIZATIONS.md#schema-drift-detection.
