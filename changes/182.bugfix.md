dbt's contract check no longer rejects a `CHAR(n)` or `BINARY(n)` column, such as a string literal like `'abc'` or a binary literal like `x'0102'`, for a column declared `string` (or `varchar`) or `bytes` (or `varbinary`). Flink types a literal as `CHAR(n)` or `BINARY(n)`, which the check compared by name with the column's `VARCHAR` or `VARBINARY`, so the model needed `CAST('abc' AS STRING)`. The schema drift check for a `streaming_table`, or a `table` with an enforced contract, accepts the same columns, so these models also re-run without reporting drift. A literal for a `varchar(n)` or `varbinary(n)` column below the maximum length is still rejected, as before: the check doesn't compare lengths, and Flink silently truncates a value longer than `n`. See MATERIALIZATIONS.md#schema-drift-detection.
