Fix `parse_unit_test_ctes` mis-slicing the main query out of a unit test's compiled SQL - previously it either left a stray leading `)`/dropped a leading character (naive `"with" + ", ".join(...)` length reconstruction didn't match dbt-core's actual injected formatting, e.g. with multiple fixture inputs) or, when the tested model's own SQL already had a `with` clause, dropped the model's own CTE definitions entirely while leaving dangling references to them. It now uses `sqlparse` - the same library dbt-core's `inject_ctes_into_sql` uses to build that clause - to find the CTE list structurally and remove only the fixture-injected CTEs, leaving any of the model's own in place.
