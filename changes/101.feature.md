`tableflow` now updates an already-enabled Tableflow config in place instead of only warning: on every run, the live `formats`/`config` are diffed against what's now configured and PATCHed only if something actually changed, avoiding a spurious restart of the backing materialization job when nothing changed. A `storage` change still can't be applied in place (Tableflow's API doesn't support it) and still requires `--full-refresh` or a manual disable. See MATERIALIZATIONS.md#tableflow.
