`tableflow` now updates an already-enabled Tableflow config in place instead of only warning: on every run, the live `formats`/`config` are diffed against what's now configured and PATCHed only if something actually changed, avoiding a spurious restart of the backing materialization job when nothing changed. A change to the `storage` configuration cannot be applied in place and will trigger a disable/enable cycle instead to replace any existing tableflow configuration. See MATERIALIZATIONS.md#tableflow.
