`organization_id`, `cloud_provider` and `cloud_region` may now be omitted from the profile with `auth: oauth` or a Global API key: the driver infers the organization (when your credentials reach exactly one) and the cloud settings (from the Kafka cluster named by `dbname`), and checks any you do set. Connecting fails with guidance naming the profile field to set when several organizations (`organization_id`) or several same-named clusters (`database_kafka_cluster_id`) match, or when `cloud_provider`/`cloud_region` disagree with the cluster. A Flink-region key still requires them, now reported when the profile loads. `dbt init` offers to infer them, and `dbt debug` leaves out the ones omitted. See the README's "Organization, cloud provider and region" section.
