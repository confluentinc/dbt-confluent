`dbt test` (unit tests) no longer requires the tested model to already exist in Confluent Cloud (i.e. a prior `dbt run`) to resolve its column names/types, and no longer risks validating against a stale, previously-deployed schema after the model's SQL changes. We now infer the column types from the model under test's query. As a side effect, this resolves a previous issue in running unit tests for models with an alias defined.
